# Evidência para aprendizado: requisitos
Data: 2026-10-13.
Objetivo observado: pesquisar e implementar melhorias verificáveis do Inonu Trader usando Jev, ML/dados e OKX Wallet/Onchain OS. Esta entrega prepara dados para avaliação local; não treina nem promove modelo.

## Fontes e estado
O contrato FeatureVector v1 admite números finitos e null, usa barras fechadas no instante observado e possui FEATURE_NAMES fixo. Snapshot/Label do recorder associam horizonte, custo round trip e retorno hipotético. O lab existente já contém custos, baselines pareados e testes estatísticos. Evitar duplicá-lo.
FreqAI exige prevenção explícita de lookahead nas features calculadas sobre a janela: https://www.freqtrade.io/en/stable/freqai-running/
TimeSeriesSplit preserva ordem temporal e admite gap; amostras igualmente espaçadas são necessárias para comparar durações: https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html
A regra abaixo de purgar pela maturação do alvo é uma decisão de projeto baseada nesses riscos, não uma certificação dessas bibliotecas.

## Aceitação imutável
LE-1: buildLearningDataset e CLI somente leem registros. CLI exige --dir, --horizon e --as-of-ms explícitos; imprime um JSON em stdout, erro fixo com contexto sem conteúdo bruto em stderr e exit 1 em falha. Não carrega .env, rede, decisões, chaves ou carteira. Apenas snapshots-YYYY-MM-DD.jsonl e labels-YYYY-MM-DD.jsonl, arquivos regulares sem links; recusa dados malformados, mais de 64 MiB ou 100000 registros. Diretório vazio produz evidência insuficiente.
LE-2: Para o horizonte escolhido, exportar apenas snapshots spot de origem relogio com custo finito não negativo, features v1 completas da whitelist, identidade de instrumento consistente, instante das features <= snapshot, timestamps inteiros seguros não negativos e idades não negativas. Preservar null e projetar somente FEATURE_NAMES. Excluir e contar registros inelegíveis; não imputar nem substituir null por zero.
LE-3: Exigir label completo, motivo null, retorno bruto/líquido long finito, maturação snapshot+horizonte <= as-of e líquido consistente com bruto menos custo (tolerância absoluta 0.000001 bps). Exportar features e target em campos distintos; target positivo equivale a líquido > 0. Identificar alvo como hipotético spot long com custo registrado, nunca lucro executado ou probabilidade calibrada.
LE-4: Snapshot id e label (snapshotId,horizonte) repetidos idênticos são deduplicados. Conflitos abortam. Dois ids para mesmo instrumento/instante abortam. Resultado determinístico independentemente da ordem de entrada; não altera objetos de entrada.
LE-5: Folds walk-forward expansivos agrupam todos os instrumentos pelo timestamp, com blocos de teste de testGroups timestamps completos e disjuntos. Treino é estritamente anterior e remove cada linha cujo labelEndMs >= testStartMs - embargoMs. minTrainGroups conta timestamps após a remoção. Blocos insuficientes são contados e omitidos; cauda incompleta não vira fold.
LE-6: Opções minTrainGroups/testGroups inteiras positivas, embargoMs inteiro não negativo, horizonte válido e as-of seguro são obrigatoriamente validadas. Relatório inclui contagens de entrada, deduplicação, motivos de exclusão, linhas, grupos temporais, folds, blocos omitidos e cauda. Zero folds significa insufficient_data; folds existentes significam ready_for_evaluation, sem alegar qualidade financeira ou independência entre alvos dentro de um teste.
LE-7: Testes exercitam a API pública e CLI com arquivos reais temporários, valores de corte literais e hashes antes/depois. Cobrem custos/null, futuros/incompletos, whitelist/proveniência, conflitos, igualdade no corte temporal, embargo e agrupamento de ativos. Typecheck das novas fontes e contratos copiados passa. Revisão independente com baseline e SPEC.
LE-8: Somente novos caminhos src/learning-evidence/**, scripts/learning-dataset.ts, scripts/learning-dataset.test.ts e docs/sdd/learning-evidence-20261013/**. Contratos preexistentes copiados apenas para a worktree e verificados por hash. Nenhuma alteração de Jev, trades, Kuru/Monad, cadence 300ms, wallet evidence, pacote ou módulos concorrentes.

## Limites e riscos
Não comprova a fidelidade point-in-time das fontes, qualidade histórica, liquidez, fills, funding, borrow, efeito causal ou retorno financeiro. O custo é uma estimativa registrada. Transações de wallet não são candles de mercado. Não preparar perp/short sem contratos completos de funding/borrow/liquidação. Durações dos testes podem diferir com falhas do recorder; comparar métricas com esses intervalos explícitos. Qualquer normalização, imputação, seleção, ajuste e calibração futura deve aprender somente no treino de cada fold. Não usar estes targets como probabilidades do Jev.
