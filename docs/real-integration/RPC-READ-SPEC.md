## Contract and invariant criteria

- R01: options inject `fetch`; no global fetch, credentials, environment, persistence or console logging. Defaults are 10,000 ms total deadline, 8 tokens, 32,768 bytes per response, 262,144 aggregate bytes and 60,000 ms TTL. Caller may only tighten these limits. No retries; maximum 4 + 4×tokenCount requests. Selection is `approved_by=jev_delegated`, real Jev Workflows receipt `3005dd1a-84ba-4cc2-af3e-4fedb8a8e0e2`, model `jev-1.13.0`, choice `small`, confidence 0.84, input/output tokens 812/60; billed USD unknown (null). Advice supplies no external authority.
- R02: input is an ephemeral EVM wallet address, chainIndex `196` or `143`, SHA-256 identityKey of UTF-8 `${chainIndex}:${address.toLowerCase()}`, nonnegative safe revision, bounded correlation ID, distinct token contract addresses and optional spender. Invalid context, missing endpoint, excess tokens or invalid token/spender address blocks before any RPC. Tokens matching the private wallet address are rejected to prevent returning that address as a token identifier.
- R03: verify `eth_chainId`, then capture `eth_getBlockByNumber("latest", false)` number/hash. Every `eth_getBalance`, `eth_getCode` and ERC20 `eth_call` uses that exact explicit block number; final `eth_getBlockByNumber(blockNumber, false)` must match both number and hash. Wrong chain, malformed context or changed block invalidates all dependent values; no mixed snapshot is usable.
- R04: native balance is canonical JSON-RPC uint256 quantity, returned as exact base-10 string. Native decimals 18 comes from the existing verified registry, never from a fabricated RPC answer. Token runtime code must be nonempty even-length hex; codeHash is Keccak-256 of those exact bytes. Standard ERC20 calls are only `balanceOf(address)`, `decimals()` and optional `allowance(address,address)`; results are exactly one ABI uint256 word. Decimals must be uint8 (0–255). Exact raw strings preserve uint256 max and real zero. Missing, malformed, errored or unobserved values stay null with bounded reason codes; unit failure never defaults to 18 or zero.
- R05: validate JSON-RPC 2.0 response ID, HTTP status and exclusive result/error shape. Provider messages and exception strings are never echoed. Receipt fields are source `evm-rpc-read`, mode `unverified`, HTTP method POST, RPC method from a fixed allowlist, endpoint host only, explicit block or null, request ID, times, HTTP status, bounded outcome/reason. No params, calldata, bodies, private wallet address, spender, raw errors, headers, logs, credential/query URL or transaction data are returned.
- R06: one deadline covers all fetches and streamed response bodies; abort cancels transport and body reader. Adapter settles even if injected transport ignores the signal. A pre-aborted caller sends no requests; after timeout/abort there are no further calls. Per-response and aggregate byte limits apply before JSON parsing; oversize and malformed payloads block, including unbounded/never-ending bodies. Temporary listeners/timers are cleaned up.
- R07: snapshot preserves identity/revision/correlation, fixed block number/hash, observation/expiry times, per-token exact rawBalance/decimals/codeHash/allowanceRaw, nativeBalanceRaw and explicit reasons. Partial token failure does not invent other values; a snapshot with any required read missing is blocked. Null allowance when no spender was requested is explicitly unrequested, not zero. Native unit method is `native-chain-metadata`; token unit method is `erc20-decimals`.
- R08: output always has `exercisedReal:false`, `financiallyQualified:false`, `executionEnabled:false`, `mode:"unverified"`, deployment null and decoder null with clear unresolved deployment/decoder dependencies. Source is RPC, never OnchainOS. Read readiness alone does not qualify an OKX deployment, ABI, spender, simulation, fee, financial result or transaction.
